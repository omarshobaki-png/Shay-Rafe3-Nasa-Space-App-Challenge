# Project brief: Space Mission Designer

**Team Shay Rafe3 · NASA Space Apps Challenge 2026 · Challenge: "Space Mission Design Game"**
Challenge page: https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/

## The game in one paragraph

A 2D pixel-art game, built in **Godot 4.7.2 with GDScript**, where students and aspiring engineers run a
whole space mission:
1. pick a destination (**Moon = Easy, Mars = Medium, Saturn = Hard**);
2. build a spacecraft from real NASA-sourced parts within a budget, with up to 4 players each owning a
   role;
3. pass a GO/NO-GO review;
4. launch, cruise (with real NASA space-weather events), land and explore, or fly a sampling drone at
   Saturn;
5. get a report that explains **why** the mission worked or failed.

Credits earned from science buy upgrades in the Tech Lab for the next try.

## Rules that can disqualify us (summary of `research/notes-rules.md`)

- **The idea must be the team's.** AI can't invent the solution. Disclose AI use in the submission's
  AI ("SI") field. The ready-made disclosure is in the root `README.md`.
- **AI images or video need a visible watermark.** We avoid the problem: all art is made by code or
  Blender scripts, and there are no AI image generators. **No NASA logos** anywhere.
- **Demo: a video of 30 s or less, OR 7 slides or fewer.** Over the limit = out of Global Judging.
  Public link, no login, English.
- Nobody under 18 may appear (face, voice or likeness) in the demo.
- Use at least one NASA data source and name it exactly (we use many; see `02_NASA_RESOURCES.md`).
- List every outside resource, including open-source code and the font (from our earlier game,
  Rotorfall).
- **Ramallah local event: projects submitted by Sun 15 Nov 2026, 15:15**; live pitches from 16:15 (3 min + 2 min Q&A); awards 19:00. The global portal closes at 23:59 local time. Judging rules and the 7-slide plan: `research/notes-pitch-and-judging.md`.

## Judging (5 criteria, each scored 1–5)

| Criterion | How we win it |
|---|---|
| Impact | Browser-playable (GitHub Pages), free, for students anywhere |
| Creativity | No existing tool does the full chain with roles + an explanation of why it failed; Saturn ring drone; pixel style |
| Validity | Real numbers with sources; a finished, playable loop; play-tested by hand |
| Relevance | NASA data drives gameplay (DONKI storms, real gravity and sunlight, JPL margins, GMAT models) |
| Presentation | A tight 30 s video showing build → fail → learn → succeed |

Awards that fit best: **Best Mission Concept**, **Best Storytelling**, **Art & Technology**, Best Use of
Data.

## Tech facts

- Godot **4.7.2**, GDScript, renderer `gl_compatibility`, base resolution **640×360**, stretch
  `canvas_items`, nearest-neighbour filtering. Autoloads: `Data`, `Game`, `Audio`.
- Web build exported to `/docs`; GitHub Pages serves it from `main` / `docs`. Windows build: the zip in
  `/builds` (not in git; upload it as a GitHub Release, since the .exe is over GitHub's 100 MB file limit).
- Assets are generated by `game/tools/` (Blender 4+/5 scripts for the ships; Python with numpy and
  Pillow for backgrounds; code-synthesized audio).
